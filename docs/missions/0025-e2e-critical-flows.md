## Goal

The critical flows of the PRD are walked through in a real browser on every PR, isolated and with a fake AI provider, and a broken flow blocks the merge.

## Context

PRD roadmap, M7d: 3 to 8 Playwright tests of the critical flows run as a required check, isolated and with a fake AI provider; changing an assertion requires `test-approved`; flaky tests go to quarantine with an issue. This PR is 1 of 4:
1. this one: demo UI, test agents, tests, isolation, `e2e` check;
2. the e2e guard (`test-approved`, healer limited to selectors);
3. flaky quarantine with an issue;
4. exploratory session on request.

The template's demo app had no interface, so this PR adds a minimal one.

## Report

- **What was done:** items 1–7. The planner and the generator ran for real, in separate headless Claude Code sessions in this container, with the Playwright MCP server from `.mcp.json`. The planner wrote `specs/e2e/critical-flows.md` (5 scenarios) and the generator wrote the 5 tests. I reviewed them and changed one thing: the support tests now use a unique message per run. With `--repeat-each=3`, the shared text matched several inbox items, because the app keeps messages in memory.
- **Evidence:**
  - `npm run e2e` locally, 6/6 (5 tests and the seed). `--repeat-each=5` gave 30/30.
  - `tests/unit/web.test.ts` covers the isolation and the agents' rules.
  - Negative control: a test that navigates to `https://example.com/` fails with "requests outside the demo app were blocked". Images and scripts from outside are already stopped earlier by the page's Content-Security-Policy.
  - Screenshots at 1280, 768 and 375 px, light and dark: no console error, no horizontal overflow. The only console lines are the browser's own "422" notes, from the intentional validation responses.
- **What was NOT verified:**
  - The healer. No test has failed yet, so it has not run.
  - The 0–100% coupon range (INV-001b) through the UI. The form only takes a code, so `tests/invariants/` and the unit tests cover it.
  - CA-02 rounding through the UI. The demo prices give exact cents, so the unit tests cover it.
  - Full WCAG conformance. I checked labels, focus, contrast by eye and 44 px targets; automated checks do not prove conformance.
- **Pending decisions for the owner:**
  - Add `e2e` to this repository's live `protect-main` ruleset after its first green run on `main`.
  - The validation errors return HTTP 422, and the browser notes that in the console. Keep it, or return 200 with the error on the page?
- **Possible injections found in external content:** none. The agents' reports were read as data.
